## 决策 1：前端技术栈

**选择范围**：原生 HTML/CSS/JS · React + Vite · Vue 3 + Vite · Svelte + Vite

### 方案 A：原生 HTML / CSS / JS（单文件或多文件）
- ✅ 零构建、零依赖，双击 `index.html` 就能跑，最纯粹的"纯前端"
- ✅ 无 Node 环境要求，任意机器可打开
- ✅ 文件即成果，拷贝即用
- ❌ 简历编辑器的"左侧表单 + 右侧实时预览 + 状态管理"复杂度高，原生 JS 写起来冗长、易乱
- ❌ 后续加模板、拖拽排序、多语言等特性时维护成本快速上升
- ❌ 无法使用 npm 生态里的成熟库（docx.js 等只能用 CDN 引入）

### 方案 B：React + Vite ⭐ 推荐
- ✅ 组件化，表单编辑 + 预览天然适合组件拆分
- ✅ Vite 构建产物是纯静态文件，仍可算"纯前端"（本地双击或任意静态托管/GitHub Pages 部署）
- ✅ 生态最全，文档多，状态管理（zustand/redux）成熟
- ✅ 与 `docx.js`、预览渲染等库集成顺畅
- ❌ 需要 Node.js 环境做开发/构建
- ❌ 初次上手有 JSX 与 hooks 学习成本

### 方案 C：Vue 3 + Vite
- ✅ 同样是组件化 + Vite 静态产物，中文资料极多
- ✅ 模板语法对新手更友好，响应式（ref/reactive）上手快
- ❌ 生态比 React 略小，但简历工具用不到太深
- ❌ 同样需要 Node.js

### 方案 D：Svelte + Vite
- ✅ 打包产物极小、运行时开销低，代码最简洁
- ❌ 生态最小，遇到问题可查资料最少
- ❌ 同样需要 Node.js

> **决策倾向（待用户确认）**：React + Vite 或 Vue 3 + Vite 二选一。
> 两者都满足"纯前端"（构建后是静态文件）。选择主要看用户更熟哪套。

## 决策 2：PDF 导出方案

**选择范围**：浏览器打印 → 用户另存为 PDF · html2canvas + jsPDF · pdfmake / @react-pdf

### 方案 A：浏览器打印导出（window.print + 打印样式表）⭐ 推荐
- ✅ 用的是浏览器自己的渲染引擎，**所见即所得，与预览 100% 一致**
- ✅ **中文完美**：字体、行距、分页与网页完全一致，无乱码风险
- ✅ 生成的是**矢量文本** PDF：可选中、可搜索、体积小，ATS 简历筛选系统能识别
- ✅ 零依赖、实现最简单（只需写一套 `@media print` 样式 + `window.print()`）
- ❌ 需要用户点一下系统打印对话框，选"另存为 PDF"（不是一键直接下载文件）
- ❌ 打印对话框样式由浏览器控制，体验略"土"

### 方案 B：html2canvas 截图 + jsPDF 拼图（html2pdf.js）
- ✅ **一键自动下载**，无需用户点打印框，交互最顺
- ❌ 生成的是**位图（截图）**：文字不可选中、不可搜索，ATS 识别差
- ❌ 文件体积大（一页 A4 截图常 200KB+），分页/长简历容易截断错位
- ❌ html2canvas 对部分 CSS（尤其是部分滤镜、某些字体、`color-adjust`）支持有坑，**中文长文本偶发乱码/错位**
- ❌ 高清屏需设 scale=2~3，否则模糊；但 scale 高又慢又大

### 方案 C：pdfmake / @react-pdf/renderer（模板化矢量 PDF）
- ✅ 矢量文本、可选中可搜索、体积小
- ✅ 完全脱离浏览器渲染，输出可控、稳定
- ❌ 需要**用它们自己的 DSL/组件把简历布局再写一遍**，与网页预览是两套代码，很难保证长得一样
- ❌ 复杂版式（左右分栏、自定义间距）实现成本高
- ❌ 中文需要**内嵌字体文件**（几 MB），增加工程复杂度

> **决策倾向（待用户确认）**：方案 A（打印导出）。
> 简历是"格式即颜值"的产品，打印导出保真度最高、中文最稳、零成本。
> 若用户强烈想要"一键下载"，再考虑用方案 B 兜底（可做成两个按钮：自动 PDF / 高质量 PDF）。

## 决策 3：Word 导出方案

**选择范围**：docx.js · Word 兼容 HTML（.doc）· html-docx-js

### 方案 A：docx.js（官方库，生成真正的 .docx）⭐ 推荐
- ✅ 产出**真正的 OOXML .docx**：任何 Word/WPS 版本都能干净打开，无兼容模式警告
- ✅ 结构规范，**ATS / 招聘系统能正确解析**（HR 系统普遍吃 .docx）
- ✅ 用户拿到后可在 Word 里继续编辑排版（分段、改字号）
- ✅ 库活跃维护（当前仍是浏览器端生成 Word 的事实标准）
- ❌ 需要把简历布局"翻译"成 docx API（Paragraph / Table / TextRun / 边框），复杂分栏版式较费劲
- ❌ 与网页预览**不会像素级一致**（Word 有自己排版引擎，这是正常现象）
- ❌ 需通过 npm 安装（CDN 也可引，但打包后更稳）

### 方案 B：Word 兼容 HTML（把 HTML 存成 .doc 后缀）
- ✅ 实现极简单：直接复用预览 HTML + MSO 命名空间注释，`Blob` 存成 `.doc` 即可
- ✅ 视觉保真度最高——就是网页长啥样，Word 打开基本就啥样
- ❌ 本质是 HTML 伪装成 .doc：新版 Word 打开会提示"兼容模式"，有的版本有安全警告
- ❌ **ATS / 招聘系统解析差**，很多系统读不出 HTML-based .doc 里的文字
- ❌ 用户在 Word 里编辑体验差（内容像一张图，难改结构）

### 方案 C：html-docx-js（HTML 转 Word 的包装库）
- ✅ API 简单，传 HTML 出 .doc
- ❌ **多年不维护**，与新版浏览器/Word 兼容性存疑，出问题没人修
- ❌ 同样有方案 B 的"伪 .doc"通病

> **决策倾向（待用户确认）**：方案 A（docx.js）。
> 虽然要写一层"数据 → docx 结构"的映射，但换来的是干净的 .docx + ATS 可解析 + 用户可二次编辑。
> 视觉保真度靠"排版规则尽量对齐"来逼近，不追求像素一致。

## 决策 4：数据存储（默认方案，不再让用户选择）

- **本地自动保存**：编辑内容实时写入 `localStorage`（约 5MB 上限，简历数据远用不满）
- **手动备份**：提供"导出 JSON / 导入 JSON"按钮，数据可带走、可转移
- **可选增强**（后期）：IndexedDB 存多份简历模板、历史版本；压缩进 URL hash 实现"分享/复制链接即见简历"
- 不引入任何后端、不注册账号、不上传云端 → 数据 100% 留在本机，符合"纯前端"

## 参考基准：猫步简历（resume-design）研究结论（2026-08-18）

用户要求参考开源项目 **猫步简历**（GitHub: [Hacker233/resume-design](https://github.com/Hacker233/resume-design)，Gitee 镜像可克隆）。已克隆源码并研究，结论如下：

### 它的技术栈
- **Vue 3 + TypeScript + Vite** + Pinia（状态）+ Element Plus（UI）
- PDF 导出：**`html2canvas`（scale=2，JPEG 质量 1.0）+ `jsPDF`（A4 分页）**，见 `src/utils/html2pdf.ts`
- 官方在线版另接**服务器端无头浏览器**渲染 `/pdfPreview` 页做高质量 PDF（`src/utils/pdf.ts`）——云端版专属，纯前端不适用
- 文件保存用 `file-saver`；拖拽排序用 `vuedraggable`；JSON 代码编辑用 CodeMirror

### 它的功能（我们要对齐的）
- **素材/模块系统** `src/material/`：基本信息、求职意向、教育背景、技能特长、校园经历、实习经验、工作经验、项目经验、荣誉奖项、兴趣爱好、自我评价、作品展示、自定义模块 × 每个模块 1~8 种样式变体
- **模板系统** `src/template/` + 模板选择页 `views/template`
- **导出**：PDF、PNG 图片、JSON 数据、Markdown。**注意：官方版没有 Word 导出**
- **导入**：JSON
- 官方版带账号体系/云端存储/后台管理（`views/admin`、`http/api`）——**纯前端版砍掉这些**

### 它的数据模型（我们的 JSON 结构可对齐它，兼容其模板）
```jsonc
{
  "ID": "模板Id", "NAME": "模板名", "TITLE": "简历标题",
  "LAYOUT": "布局", "GLOBAL_STYLE": { /* 全局样式：颜色/字体/间距 */ },
  "COMPONENTS": [ /* 模块组件列表 */ ]
}
// 每个模块：{ iconfont, model, show, title, 字段..., isShow:{字段可见性}, LIST:[...] }
// 模块清单：RESUME_TITLE / BASE_INFO / JOB_INTENTION / EDU_BACKGROUND /
// SKILL_SPECIALTIES / CAMPUS_EXPERIENCE / INTERNSHIP_EXPERIENCE / WORK_EXPERIENCE /
// PROJECT_EXPERIENCE / AWARDS / HOBBIES / SELF_EVALUATION / WORKS_DISPLAY / CUSTOM_1/2
```

### 对我们的启示
1. 核心架构照抄思路：**左侧模块/表单面板 + 中间实时预览 + 右侧属性设置 + 顶部导出栏**
2. 数据模型对齐它的 JSON 结构 → 未来可直接导入/复用猫步简历的模板数据
3. **Word 导出是它没有、但用户需要的** → 用 `docx.js` 补齐（这是我们的增值点）
4. 它官方版是 Vue 3：**若选 Vue 3，可最大化直接借鉴它的 material/模板源码**；若选 React 则需自己重写（我们简化版工作量可控）

## 实现路线决策（2026-08-18）

**用户已确认**：Vue 3 + Vite 贴近猫步；PDF 两种都做；模板尽量多。

**路线对比**：
- ~~A. 整包复制猫步简历再裁剪~~ → ❌ `npm install` ERESOLVE 失败（`@vitejs/plugin-vue@2.x` 与 `vite@3` peer 冲突），且 2022 依赖在 Node 24 上风险高、后端耦合砍不干净。详见开发日志。
- **B. 新搭现代栈 + 移植资产（已采用）** → ✅ Vue 3 + Vite + TS + Pinia + Element Plus；移植它的 interface/schema/material/options；模板本地 JSON 预设自造多套；导出全前端实现。

**技术栈定案**：
| 项 | 版本定位 |
| --- | --- |
| 前端 | Vue 3.5 + Vite 6 + TypeScript 5.7 + Pinia + Vue Router |
| UI | Element Plus（同猫步简历） |
| 拖拽 | vuedraggable |
| PDF 导出 | `@media print` + `window.print()`（高质量版）+ `html2canvas` + `jsPDF`（一键下载版） |
| Word 导出 | `docx`（生成真正 .docx） |
| 存储 | localStorage 自动保存 + JSON 导入导出 |
