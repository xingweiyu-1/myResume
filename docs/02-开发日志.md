## 2026-08-18 · 移植猫步简历素材组件时踩的坑（批量）

**背景**：确定"新搭现代栈 + 移植资产"路线后，把猫步简历的 `material/`（124 个组件）、`options/`（21 个属性面板）、`hooks/`、`components/ModelComs`、`config` 整体拷贝进项目，然后修依赖。

**问题清单与解决**：
1. **SCSS 变量未定义**（`$primary-text-font-size` 等）→ 原版靠 vite `additionalData` 全局注入 `@use "src/style/global.scss" as *`，照抄配置即解决。
2. **`color-picker` 组件无法解析**（原版第三方库 `colorpicker-v3`）→ 用 Element Plus 自带 `el-color-picker` 重写 `ColorPickerCustom.vue`，保持原组件接口（`modelValue` + `change` 事件）。
3. **头像上传走服务器**（`el-upload :action` + token 头）→ 纯前端改为**本地 FileReader 转 base64**，头像随简历 JSON 存 localStorage / 导出。
4. **`@/interface/modelStyle.js` 后缀导入** → 改成无后缀。
5. **isolatedModules 下 `export {}` 类型报错** → 改 `export type {}`；`ICUSTOM1/2` 被我合并进 `ICUSTOM`，补类型别名兼容。
6. **`ref/reactive/computed` 未导入**（原版用 unplugin-auto-import）→ 项目加 `unplugin-auto-import`，vite 配置 `imports: ['vue', 'vue-router']`。
7. **materialList 是命名导出** → 改 `import { MATERIAL_JSON }`。
8. **新版 Element Plus 的 `ElMessage` 没有 `center` 选项** → 全部移除。
9. **jsPDF 构造签名**：`new JsPDF('', 'pt', 'a4')` 第一个参数不合法 → 改 `new JsPDF({ orientation: 'portrait', unit: 'pt', format: 'a4' })`。
10. **素材组件引用本地图片**（`j1_span.png` 等）→ 整体拷贝 `assets/images/`（4.8MB, 130 文件）。

**结果**：✅ `vue-tsc --noEmit` 0 错误，`vite build` 通过。

## 2026-08-18 · 浏览器验证环节的坑（重要经验）

**问题**：用 puppeteer-core 驱动系统 Edge 做渲染验证，发现"首页 → 点模板进设计器"偶发空白页，且带 `GlobalStyleOptions` 报错，排查很久。

**真相**：`page.goto()` 导航到一个**仅 hash 变化**的 URL（`/#/` → `/#/designer?...`）时，**Chrome 有时不触发 `hashchange` 事件**，Vue Router（hash 模式）收不到导航，页面停留在首页。**这是测试脚本的假象，不是应用 bug**。真实用户点卡片走的是 `router.push()`（会正确触发 hashchange），或整页刷新，均正常。

**已验证**：生产构建下模拟真实路径（点击卡片）→ 路由正确、9 模块渲染、零错误。

**经验**：
- 测 SPA hash 路由时，用 `page.evaluate(() => { location.hash = ... })` 导航（稳定触发 hashchange），不要用 `page.goto()` 做 hash 变更。
- 测试脚本要在**生产构建**（`vite preview`）上跑，排除 dev 按需编译干扰。
- 顺带做了健壮性修复：store 的 `changeResumeJsonData` 保证 `GLOBAL_STYLE`/`COMPONENTS` 始终存在；`GlobalStyleOptions` 的 setup 读取加可选链。

**另一个坑**：puppeteer 下载文件时 `Page.setDownloadBehavior` 的 `downloadPath` 必须传**绝对路径**，相对路径会被忽略（表现为"点击了但没下载"）。

**结果**：✅ 全部功能在真实路径下验证通过。

## 2026-08-18 · 猫步简历旧依赖在 Node 24 上装不上 → 定案"新搭+移植"

**问题**：原计划"复制猫步简历源码裁剪成纯前端"，但 `npm install` 直接失败：
```
npm error ERESOLVE unable to resolve dependency tree
npm error Found: vite@3.2.11
npm error Could not resolve dependency:
npm error peer vite@"^2.5.10" from @vitejs/plugin-vue@2.3.4
```
即 `@vitejs/plugin-vue@2.x` 声明只支持 `vite@^2.5.10`，与项目里 `vite@^3` 冲突。这只是第一处，后面还有 Vue 3.2 / TS 4.5 / vue-tsc 0.29 等一堆 2022 年老依赖要过 Node 24 这一关。

**排查过程**：先试 GitHub 克隆（超时）→ Gitee 克隆（成功）→ 读源码理解耦合度（发现登录/后台/云存储/服务端PDF渲染全在后端，前端深度耦合）→ 试装依赖（ERESOLVE 失败）。

**解决方案（定案）**：**放弃整包裁剪**，改为：
1. **新搭现代栈**：Vue 3 + Vite + TS + Pinia + Element Plus（Node 24 兼容）
2. **移植核心资产**（MIT 许可，保留出处）：数据模型（interface/schema）、素材组件（material/）、属性面板（options/）、设计器布局概念（左模块/中预览/右属性）
3. 模板做成**本地 JSON 预设**（LAYOUT + GLOBAL_STYLE + COMPONENTS），自造多套，质量可控、直接可用
4. 导出全部前端实现：PDF（打印 + html2canvas 两套）、Word（docx.js）、JSON

**结果**：✅ 已定案。教训：**2022 年老项目 + 2026 年 Node 24 = 依赖地狱，能移植资产就别整包搬**。

## 2026-08-18 · 研究猫步简历时踩的坑

**问题 1：GitHub 直连超时**
- 现象：`git clone https://github.com/Hacker233/resume-design.git` 3 分钟超时（国内网络直连 GitHub 慢/不稳）。
- 解决：换 **Gitee 镜像** `https://gitee.com/sorryback/resume-design.git`，秒下。
- 结论：**国内拉开源项目优先 Gitee 镜像**；拉之前 `Remove-Item` 清掉上次残留的半成品目录，否则报 "destination path already exists"。

**问题 2：WebFetch 被网络策略全部拦截**
- 现象：`WebFetch` 访问 github.com / raw.githubusercontent.com / cloud.tencent.com / appinn 全部报 "Unable to verify if domain ... is safe to fetch"。
- 解决：改用 `WebSearch`（可用）查技术细节 + 直接 `git clone` 源码研读。
- 结论：**这个环境里 WebFetch 基本不可用，需要联网资料时走 WebSearch + 克隆源码**。
